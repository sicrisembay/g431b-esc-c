# G431B ESC Controller Firmware

## Overview
This repository contains the firmware for a brushless ESC (electronic speed controller) based on the STM32G431 microcontroller. The project combines the QP/C real-time framework, CANopenNode v4, and ST's HAL drivers to deliver a deterministic, CANopen-compliant motor-control platform that can integrate into larger automation networks.

Key capabilities include:
- Real-time tasking with the preemptive **QXK** kernel from the QP/C suite
- **CANopen** communication stack built on top of the FDCAN peripheral
- High-resolution current and voltage acquisition via dual ADCs and on-chip OPAMPs
- Flexible timer configuration for PWM generation, time bases, and profiling

The firmware is designed for use with the **STM32G431CBU6** MCU and is generated/maintained with STM32CubeMX and QM tooling.

## Repository Structure
```
components/
  app/          → Auto-generated CANopen Object Dictionary (OD.c/OD.h) and XDD source
  canopen/      → CANopen active object, driver glue, QM model, application layer
  qpc/          → QP/C framework sources, ports, and third-party middleware
Core/
  Inc/          → HAL-generated headers (main.h, interrupt vectors, configs)
  Src/          → HAL-generated source files (main.c, init code, IRQ handlers)
Debug/          → Build artifacts created by STM32CubeIDE/Makefile build
Drivers/        → CMSIS device headers and STM32 HAL drivers
Startup/        → Cortex-M startup assembly and linker scripts

Project files:
- `g431b-esc-c.ioc`  → STM32CubeMX hardware configuration
- `components/canopen/canopen.qmp` → QM state machine model
- `Debug/makefile`   → Generated GNU Make project for building in Debug mode
```

## Firmware Architecture
### Runtime Framework
- **QP/C (QXK kernel)** powers the event-driven active object design.
- `components/qpc_hooks.c` instantiates the application active objects and configures the kernel.

### CANopen Integration
- `components/canopen/CO_driver.c` implements the CANopenNode driver hooks on top of STM32 HAL FDCAN APIs.
- `components/canopen/AO_canopen.c` defines the CANopen active object, responsible for:
  - Initialising the CANopen stack and CAN filters
  - Transitioning through ALLOCATE → COMM_INIT → RUNNING states
  - Processing 10 ms and 1 ms ticks, as well as receive-triggered events

### Object Dictionary
- Generated by CANopenEditor; primary sources are `components/app/g431b-esc.xdd` and the compiled outputs `OD.c/OD.h`.
- Producer heartbeat (1017h) starts at 2 s, consumer heartbeat array currently supports one monitored node.

### Diagnostics & Logging
- QS trace instrumentation is enabled throughout the CANopen driver for critical error reporting (e.g., bus-off, RX overflow, TPDO lateness).
- `TIMER_1us_count()` provides μs-resolution timing for stack diagnostics and TPDO timing.

## Build & Flash Instructions
1. **Toolchain**: STM32CubeIDE 1.16 (or newer) or arm-none-eabi-gcc toolchain compatible with STM32CubeMX 6.15 projects.
2. **Regenerate HAL/QP code** (optional):
   - Launch STM32CubeMX with `g431b-esc-c.ioc` to adjust hardware configuration.
   - Launch QM 7.0.x with `components/canopen/canopen.qmp` for active-object edits.
3. **Build**:
   - Using STM32CubeIDE: Import the project (`File → Open Projects from File System`), select Debug configuration, and build.
   - Using command line: From `Debug/` run `make` (requires GNU Make and arm-none-eabi toolchain in PATH).
4. **Flash**:
   - Connect ST-LINK; use STM32CubeIDE Run/Debug or `ST-LINK_CLI -c SWD -P Debug/g431b-esc-c.bin 0x08000000 -V`.

## Getting Started
1. **Hardware Setup**: Ensure FDCAN transceiver is connected (pins PA11/PA12) with proper termination; TIM1 outputs map to motor phases.
2. **Power & Reset**: Apply system power, perform hardware reset; firmware boots into CANopen pre-operational state.
3. **CANopen Commissioning**:
   - Node-ID default: `10` (decimal)
   - Bit-rate: `1 Mbps` nominal with CAN-FD BRS enabled for data phase
   - Heartbeat producer: 2 s period
   - Consumer heartbeat array: one entry (disabled by default)
4. **Monitoring**:
   - Use CANopen master or analyzer to send NMT start command.
   - Observe QS traces (via QSPY) for diagnostic output over UART2.

## Key Configuration Points
- **Auto-Retransmission**: Enabled in `MX_FDCAN1_Init()` and `.ioc` to retry CAN frames automatically.
- **Interrupt Priorities**: FDCAN1_IT0 is configured as QF-aware to satisfy QP/C requirements (priority ≥ 3).
- **Timers**:
  - TIM2: 1 µs free-running counter for timestamps
  - TIM3: 1 ms system tick driving the QP time base
- **ADC/OPAMP**: Dual ADC sequencers capture motor phase currents/voltages through on-chip op-amps.

## Extending the Firmware
- Modify CANopen OD entries in `g431b-esc.xdd`, regenerate using CANopenEditor, and rebuild.
- Add application-specific active objects within `components/` and register them in `qpc_hooks.c`.
- Integrate additional sensors or control loops by extending HAL initialisation in `Core/Src/main.c`.

## Troubleshooting
- **Bus-Off / Error Passive**: QS logs emit detailed messages; inspect CAN wiring and termination.
- **Rx Overflow**: Firmware logs FDCAN FIFO overflows and raises CANopen error register bits; consider adjusting PDO frequency or adding buffering.
- **Timing Issues**: Verify TIM2/TIM3 clocks and ensure `HAL_Init()`/`SystemClock_Config()` were not modified inadvertently.
